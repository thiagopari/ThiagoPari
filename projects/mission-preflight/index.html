Mission Preflight: Sandboxed Checks for ROV Missions

Vultr Agent Rush (lablab.ai), Nov 2026 · solo · built with Kiro

PythonKata ContainersVultr Serverless InferenceVultr Cloud ComputeKiro
✓ Submitted Nov 8, 2026
Real vs. simulated: The ROV scenes are rendered in NVIDIA Isaac Sim. The checks, microVMs and verdicts are live runs on a Vultr VM.

The Problem

One bad waypoint can lose the vehicle, and mission plans and vendor scripts are untrusted code.

How It Works

  1. The plan and the vendor script come in as untrusted code.
  2. Vultr Serverless Inference writes the checks (checks.py).
  3. Each step runs in its own Kata microVM on a Vultr VX1 with nested virtualization, destroyed after the run.
  4. The host, not the model, returns APPROVE or BLOCK.

Three Live Runs

  1. Pier survey: every check passes (2,557 tokens)
  2. 65 m dive on a vehicle rated for 50 m, still blocked after a patch
  3. Contractor script with a prompt injection: blocked, and the vendor process was OOM-killed (2,769 tokens)
