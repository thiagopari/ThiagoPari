Overview

AI-powered desktop assistant combining mechanical engineering, embedded systems, and large language models. The 14-inch animatronic features a custom dual-axis eye mechanism with four-bar linkages, controlled by an ESP32-S3 with built-in camera and microphone. The AI system uses a hybrid local/cloud architecture running Qwen 2.5 7B locally for ~90% of queries with GPT-4o-mini fallback for complex reasoning, achieving significant cost savings while maintaining quality.

Current Status: CAD design complete, all structural components 3D printed and assembled. Currently testing and calibrating servo ranges for smooth coordinated eye movement. AI system fully operational with tool-use framework including web search, browser automation, and code execution.

Mechanical Design

Custom dual-axis eye mechanism designed in Fusion 360 using spatial four-bar linkages to convert servo rotations into realistic eye movements. Each eye has independent pan and tilt control.

  • Linkage geometry: Four-bar mechanism achieving symmetric ±30° range of motion for both axes
  • Servo selection: 4× SG90 servos controlling dual-axis eye mechanism
  • Integration: Component mounts for electronics integrated directly into body structure
  • Fabrication: All structural components 3D printed, iterating on tolerances for servo mounts and linkage pins

Embedded Systems Architecture

Streamlined architecture using XIAO ESP32-S3 Sense as the central controller, eliminating the need for separate microcontrollers:

  • XIAO ESP32-S3 Sense: All-in-one module with built-in OV2640 camera and PDM microphone, handling video/audio capture and WiFi communication to laptop
  • PCA9685: 16-channel I2C PWM driver controlling 4 SG90 servos with 12-bit resolution
  • MAX98357A: I2S amplifier driving speaker for voice output
  • Power system: Multi-rail distribution (3.3V, 5V, 6V) with appropriate voltage regulation and decoupling capacitors
  • Communication: WiFi (ESP32-S3 ↔ Laptop for AI processing), I2C (ESP32-S3 ↔ PCA9685 for servo control)

Hybrid AI Architecture

Intelligent routing between local and cloud models based on query complexity, optimizing for both cost and quality:

  • Local LLM: Qwen 2.5 7B running via Ollama on RTX Pro 2000 GPU, handling ~90% of queries
  • Cloud API: GPT-4o-mini for complex reasoning and multi-step tasks requiring stronger capabilities
  • Intelligent routing: Complexity scoring algorithm analyzing query characteristics to determine optimal model
  • Cost efficiency: ~90% cost reduction compared to all-cloud approach while maintaining response quality

Agentic Tool Framework

The AI system includes autonomous tool-use capabilities through function calling:

  • Web search: Real-time information retrieval for current events and fact-checking
  • Browser automation: Selenium-based web interaction with DOM element analysis, achieving 95%+ reliability
  • Code execution: Python file creation and execution in sandboxed environment
  • Memory systems: ChromaDB for episodic conversation memory, SQLite for structured user facts

Memory & Context

Dual-memory architecture enables personalized, context-aware responses:

  • Episodic memory: ChromaDB vector database storing conversation embeddings for semantic search
  • Semantic memory: SQLite database for structured facts (user profile, preferences)
  • Context injection: Automatic retrieval of relevant past conversations prepended to each query
