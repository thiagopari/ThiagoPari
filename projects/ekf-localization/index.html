Overview

Real-time sensor fusion of wheel odometry, IMU and simulated GPS with Extended and Unscented Kalman Filters, for mobile robot localization in Gazebo. Fusing odometry, IMU and simulated GPS cut RMS position error by 28.8% compared to a dead-reckoning baseline.

Note: LiDAR did not run in the Gazebo simulation (GPU limits under Parallels on Apple Silicon), so the results below use odometry, IMU and simulated GPS only.

Key Achievement: EKF and UKF written from scratch in Python as a ROS 2 node, running at 50 Hz with full covariance propagation.

Technical Implementation

Extended Kalman Filter (EKF)

The EKF implements full prediction and update cycles with proper Jacobian linearization for non-linear motion models. The prediction step uses differential drive kinematics with mid-point integration to estimate the next state:

State vector: x = [x, y, θ]ᵀ where (x, y) is position in meters and θ is heading in radians.

Motion model propagates state using wheel velocities while computing the Jacobian matrix for covariance updates. The update step fuses GPS position and IMU heading measurements using the standard Kalman gain formulation. A LiDAR scan-matching update is written but not yet run in simulation.

LiDAR Scan-Matching Update (written, not yet run)

A multi-resolution trimmed ICP update (voxel sizes 0.1, 0.05 and 0.02 m; closest 80% of correspondences kept; measurement noise scaled by fit quality). Tested on synthetic point sets only; it has not run inside the Gazebo simulation.

Unscented Kalman Filter (UKF) Comparison

A parallel UKF using sigma-point transforms serves as a comparison baseline. The two filters tie to the millimeter (see Limitations).

System Architecture

The system runs as a ROS2 node orchestrating multiple asynchronous sensor callbacks. Key components include:

  • Motion Prediction: 50 Hz updates using wheel odometry velocities with full covariance propagation
  • IMU Updates: 50 Hz heading corrections (configured noise: 1°)
  • GPS Updates: 1 Hz simulated position fixes (the simulator's /odom pose plus ~30 cm noise)
  • Scan Matching: trimmed ICP position update (written; not yet run in the simulation)
  • Dead Reckoning Baseline: Pure odometry integration without corrections for performance comparison

Robustness Features

GPS Outage Handling

With GPS outage simulation enabled, the filter keeps running through 15-second GPS losses, predicting from odometry and correcting with the IMU. RViz covariance ellipses show the uncertainty growing during an outage and shrinking after GPS returns.

Real-Time Visualization

RViz integration provides live visualization of estimated trajectory, uncertainty ellipses, and comparison against the /odom reference pose. The uncertainty visualization dynamically updates based on filter confidence, expanding between GPS updates and contracting after measurement corrections.

Simulated Platform (Gazebo)

Simulated TurtleBot3 Waffle with:

  • Wheel encoders providing differential drive odometry
  • IMU for heading measurements
  • 360° LiDAR (scan-matching update not yet run)
  • Simulated GPS: the /odom pose plus ~30 cm noise

Limitations

  • Simulation only; no hardware run yet.
  • GPS is simulated as the /odom pose plus noise, and error is measured against that same /odom pose, not Gazebo's true pose.
  • The LiDAR scan-matching update has not run in the simulation, so it is not part of the results above.
  • Fused RMS error (1.58 m) is about 5× the simulated GPS noise (σ = 0.3 m), and EKF and UKF agree to the millimeter; the cause is not traced yet.
